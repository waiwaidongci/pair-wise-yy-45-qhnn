# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定、离线协同合并与修订历史。

## 技术栈

React + MUI + Redux Toolkit + React Router + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62045`。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、填写未提交草稿，审核完成后锁定轮次并保留完整历史。

## 离线协同合并（款式档案 / 样衣评审 / 修订历史共享同一流程）

产品与版师可同时离线改同一款样衣，不再“谁后保存谁覆盖”：

- **每次操作带提交人和基准版本**：字段编辑、批注、方案决定都先暂存为一笔带 `author + baseVersion` 的改动。
- **离线改动回来合并**：在“协同合并中心”点同步；可先切换离线模式编辑，再恢复在线同步。
- **字段级三方合并**：基准值 / 服务端现值 / 离线新值三方比较。未冲突内容自动合入；同一字段双方都改且结果不同，冲突留两份并写明双方来源，逐条选择「保留服务端 / 采用离线稿 / 自定义合并值」。
- **基准版本过期拒绝整稿写入**：服务端版本已推进时，旧稿不会整体覆盖，只合并不冲突部分，冲突进入待处理分支。
- **审核锁定与已定方案照常保留**：锁定资料、已采纳/未采纳方案受保护，旧稿写入被拦下并记录原因。
- **同步失败留下待处理分支**：离线/失败时改动落为持久化分支（localStorage，重开页面仍在），可指派责任人重试或放弃。
- **历史还原逐字段取舍**：版本时间线可打开任意历史版本，勾选字段还原，每次还原生成新版本，历史永不被覆盖。

页面底部“协同合并中心”提供身份切换、在线/离线开关、「模拟协作者后保存」（用于制造基准过期与同字段冲突）、分支指派与重试入口。
